# 長寿社会シミュレーション – LLMハッカソン

このプロジェクトは、平均寿命が約 **200 年** に伸び、外見が若いまま生き続ける世界で、人々の行動がどのように変化するかをシンプルなエージェントベースのシミュレーションで探るものです。長寿社会では、再教育やキャリアチェンジ、家族形成などのライフイベントが従来とは異なるタイミングで発生すると考えられます。本リポジトリには、そのような未来社会を軽量に再現するための Python スクリプトと設定ファイルが含まれています。

**既定では LLM（ローカル Ollama 等）は無効**です。ヒューリスティックのみで動き、Ollama 未起動でも負荷がかかりません。`config.yaml` で `llm.enabled: true` にすると、エージェントが順番にローカル API へ問い合わせて移動先を選びます。応答が続けて失敗した場合は `failure_limit` 回で自動的に LLM をオフにし、ヒューリスティックへ切り替わります。

## プロジェクト構成

```
LLM-hackathon-project/
├── README.md           # 本ファイル
├── config.yaml         # シミュレーション設定（YAML）
├── agent.py            # エージェントのクラス定義
├── simulation.py       # シミュレーションの本体
├── main.py             # 実行用エントリーポイント
└── requirements.txt    # 必要な Python パッケージ
```

### 各ファイルの役割

* `config.yaml` – 世界のサイズや場所の座標、エージェント数、シミュレーション時間などを定義します。数値を調整することで計算負荷を増減させることができます。
* `agent.py` – エージェントの属性（年齢や志向など）をランダムに生成し、どの場所へ向かうかを決めます。既定は指向に基づくヒューリスティックです。LLM 有効時は JSON で `target_place` を返す応答を解釈し、壊れた JSON でも部分的に抽出を試みます。
* `simulation.py` – YAML 設定を読み込み、エージェントと場所を作成し、時間ステップごとにエージェントを動かします。実行後、`output_longevity/`（設定の `visualization.output_dir`）に `summary.txt`、`visits.csv`、`replay.json` を出力します。`save_frames: true` のとき PPM 連番フレームを書き、`ffmpeg` が PATH にあれば `simulation.mp4` を自動生成します。
* `main.py` – コマンドライン引数を処理し、`Simulation` クラスを起動するための薄いラッパーです。
* `requirements.txt` – `pyyaml` だけを依存関係として使用しています（標準ライブラリのみ追加）。HTTP でローカル LLM に接続するときも追加パッケージは不要です。
* `replay_viewer.html` – `output_longevity/replay.json` をブラウザで再生する簡易ビューアです。

## 長寿シナリオの前提

本シミュレーションでは、次のような前提を置いています。

* **平均寿命と外見**: 人間の平均寿命は 200 年程度で、180 歳頃まで 30 代のような外見を維持します。
* **生殖可能期間**: 18 歳から約 150 歳まで子どもをもうけることができます。
* **定年なし**: 定年制がなく、どの年齢でも働き続けたり、学び直したり、起業に挑戦することができます。
* **社会イベント**: 従来の「火災」の代わりに、年金改革や出生制限議論、若返り治療の価格上昇などの政策イベントが起こります。簡易版ではイベントの影響は実装していませんが、設定ファイルに含めて将来拡張できるようにしています。
* **エージェントの属性**: 各エージェントには年齢や志向（家族志向、キャリア志向、学習志向、長期志向、リスク許容度など）が割り当てられています。これらの志向は 0.0〜1.0 の範囲でランダムに決まり、どの場所を優先するかを決める要因になります。

## 実行方法

シミュレーションを実行するには、以下の手順を参考にしてください。

1. Python 3.9 以上がインストールされていることを確認します。
2. リポジトリのルートに移動し、依存関係をインストールします。

   ```bash
   pip install -r requirements.txt
   ```

3. 設定ファイル（`config.yaml`）を必要に応じて編集します。初期設定では、30 名のエージェントが 100 ステップの間、7 つの場所を移動します。計算負荷を下げたい場合は、エージェント数やステップ数を減らしてください。
4. シミュレーションを起動します。

   ```bash
   python main.py --config config.yaml
   ```

   オプションで `--seed` を指定すると、ランダムシードを固定して同じ結果を再現できます。

5. 実行が終了すると、標準出力に各場所への訪問回数や経過時間が表示されます。ログファイルは `config.yaml` の `logging.log_file`（初期値は `simulation_longevity.log`）に保存され、成果物は `output_longevity/` にまとまります。

### 成果物とリプレイ

| ファイル | 内容 |
|----------|------|
| `summary.txt` | ステップ数、経過時間、訪問集計、LLM の成否のサマリ |
| `visits.csv` | 施設に「入場」したイベント（ステップ、エージェント ID、場所名） |
| `replay.json` | 各ステップの全エージェント座標・滞在場所 |
| `frames/frame_*.ppm` | 鳥瞰ビューの連番画像（`save_frames` 時） |
| `simulation.mp4` | `ffmpeg` 利用可能時のみ自動生成 |
| `replay_viewer.html` | `replay.json` を読み込むビューア（同一フォルダで `python -m http.server` の後にブラウザで開くと確実） |

### Ollama を有効にする場合

1. [Ollama](https://ollama.com/) を起動し、`config.yaml` の `llm.model` で指定したモデルを取得済みにします。
2. `llm.enabled: true` に変更します。
3. 失敗が `failure_limit` 回続くと自動で LLM が無効化され、以降はヒューリスティックのみになります。

## ゲーミング PC での動作

LLM を無効にした状態では重い推論を行わないため、一般的なゲーミング PC でも問題なく実行できます。LLM を有効にした場合はステップあたり最大 1 回の API 呼び出しに抑えていますが、モデル選びや実行時間は環境に依存します。例えば、8 コア以上の CPU と 16 GB 以上のメモリを搭載した 30 万円前後の PC であれば、数百ステップ・数十エージェント規模のシミュレーションを数秒〜数十秒で完了できます。設定値を小さくすればさらに短時間で終わります。

## 自由にカスタマイズ

* `config.yaml` の `places` セクションに新しい場所を追加したり、座標や収容人数を変更することができます。
* `fires` セクションに社会イベントを定義し、将来的にエージェントの行動に影響を与えるロジックを追加することもできます。
* `agent.py` のロジックを発展させて、志向や年齢に応じたより複雑な意思決定やコミュニケーションを実装することも可能です。

このリポジトリは自由にフォークして実験できます。長寿社会で起こりうる様々な行動や制度変化をシミュレーションし、自分なりの KPI（初婚年齢、子ども数、転職回数、再教育回数など）を計測してみてください。
